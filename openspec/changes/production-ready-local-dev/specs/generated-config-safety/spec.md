# Spec Delta

## Purpose

The existing regenerate and verify commands produce stable bytes.

## ADDED Requirements

### Requirement: Generation is deterministic
Given the same `service.json`, TDK version, and generator inputs, `tdk config regenerate` SHALL produce byte-identical output. Generated files SHALL NOT contain timestamps, random identifiers, machine-specific absolute paths, or ordering that depends on filesystem or environment iteration order.

#### Scenario: Two regenerations match
- **WHEN** `tdk config regenerate` runs twice without input changes
- **THEN** the generated files are byte-identical and `tdk config verify` exits 0

### Requirement: Generated files identify their source
Every generated artifact SHALL include a header that says it was generated by TDK, names its source, says not to edit it by hand, and says to regenerate with `tdk config regenerate`.

#### Scenario: Developer opens a generated Dockerfile
- **WHEN** a generated Dockerfile is opened
- **THEN** the header includes `Generated by TDK` and `tdk config regenerate`

### Requirement: Verify names every drifted path
`tdk config verify` SHALL list each drifted generated path and SHALL tell the user to run `tdk config regenerate`. It SHALL exit 1 if any generated file differs and 0 if none differ. A second verify on unchanged files SHALL exit with the same code.

#### Scenario: Two generated files differ
- **WHEN** a generated Dockerfile and a generated Tilt file differ
- **THEN** verify names both paths, mentions `tdk config regenerate`, and exits 1
