# Design

## Context

Doctor already returns `schemaVersion: 1`, `data.ready`, `data.inProject`, `data.checks`, optional `data.host` and `data.ports`, and `errors`. `getDoctorExitCode` is 0 when ready (warnings allowed), 1 for a blocking check, and 2 when `errors` is non-empty (usage or internal). Human output already ends with `Doctor passed. Next: tdk up` or `Doctor failed. Fix the items above, then run: tdk doctor`. `tdk logs` already takes `--service`, `--tail`, `--since`, `--port`, and `--json`.

## Goals / Non-Goals

- Goals: those contracts stay stable. Repeated runs agree. Generated bytes agree. Status, UI, and logs do not disagree about a failed service.
- Non-Goals: a new JSON shape, a new `Ready: yes` banner, `tdk generate`, `--follow` on logs, a diagnostics command, a lock file, native Windows runtime.

## Decisions

- Doctor JSON stays the envelope in `cli/src/utils/doctor-report.ts`. Do not flatten it to `{ ready, checks }`. `--json` does not change which checks run.
- Exit 2 stays "usage or internal", matching `getDoctorExitCode`. Do not narrow it to usage only.
- Human doctor outcome lines stay the current strings. Grouping may be added only if those lines still appear.
- Drift stays on `tdk config verify`. The fix hint stays `tdk config regenerate`.
- Logs stay a bounded snapshot. Unknown service and bad flags stay exit 2. Tilt connection failure still names `tdk up`.
- Port fallback stays the existing bounded ranges. Doctor JSON `data.ports` already has requested, chosen, explicit, and reason. Human output must show the same chosen port.
- Secrets stay redacted in doctor JSON, logs JSON, and errors.
- Schema migration stays `tdk config migrate`. No silent `service.json` rewrite.

## Risks / Trade-offs

- Issue #661 asks for `tdk generate --check` and a new doctor layout. This change maps the check to `tdk config verify` and keeps the current doctor contract, so existing scripts do not break.

## Migration Plan

No command renames. No JSON shape change. Existing `service.json` stays valid.

## Open Questions

- None that block this change.
