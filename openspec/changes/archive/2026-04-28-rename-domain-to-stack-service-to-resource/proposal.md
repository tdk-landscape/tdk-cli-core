## Why

The codebase currently uses inconsistent terminology: "domain" vs "stack" and "service" vs "resource" are used interchangeably, causing confusion. The manifest schema has migrated from `domain` to `stack` as the preferred field, and the architecture has shifted from "services" to "resources" as the core abstraction. Standardizing on "stack" (for grouping/organizing) and "resource" (for individual deployable units) will clarify the mental model and reduce cognitive overhead for developers working across 174+ .star files.

## What Changes

- **BREAKING** Rename all `domain` references to `stack` in manifest field access patterns (`manifest.get('domain')` → `manifest.get('stack')`)
- **BREAKING** Rename `domain_configs` cache key to `stack_configs`
- **BREAKING** Rename `_render_product_domains_index()` function to `_render_product_stacks_index()`
- **BREAKING** Update all function docstrings and comments from "service" to "resource" terminology
- **BREAKING** Rename variables like `svc` to `resource`, `service` to `resource` throughout
- Remove fallback patterns like `manifest.get('stack') or manifest.get('domain')` and use only `stack`
- Update autogenerated file names from `domains` to `stacks`
