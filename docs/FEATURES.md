# TDK Features Reference

This document describes all available features in TDK and how to control them.

## Overview

TDK has two levels of feature control:

1. **Project-Level Features** - Infrastructure services available to all resources (proxy, database, etc.)
2. **Resource-Level Features** - Code generators for individual services (api-client, prisma, etc.)

---

## Project-Level Features

Project-level features are configured in `.tdk/project.json` and control infrastructure services.

### CORE Features (Pre-Enabled)

These are always enabled in the `pre_alpha` stack:

#### `proxy` (Traefik)
- **Purpose**: Reverse proxy and API gateway for routing all services
- **Default**: ✅ Enabled
- **Service Name**: `proxy`
- **Port**: 80 (HTTP), 443 (HTTPS)
- **Configuration**: Routes all HTTP traffic based on path/domain rules

#### `registry` (Verdaccio)
- **Purpose**: Local npm registry for package management and publishing
- **Default**: ✅ Enabled
- **Service Name**: `verdaccio`
- **Port**: 4873
- **Configuration**: All services use this for `npm install` and `bun install`

#### `database-management` (PostgreSQL)
- **Purpose**: Primary relational database for data persistence
- **Default**: ✅ Enabled
- **Service Name**: `database-management`
- **Port**: 5432
- **Database**: `app_dev` (default)
- **Configuration**: Backend services use `DATABASE_URL` env var

### OPTIONAL Features (Disabled by Default)

Enable these in `.tdk/project.json` under `optional_infra`:

```json
{
  "optional_infra": {
    "monitoring": true,
    "elk": true,
    "debezium": true,
    "golden_image": true
  }
}
```

#### `monitoring` (SigNoz/SkyWalking)
- **Purpose**: Observability platform for metrics, traces, and logs
- **Default**: ❌ Disabled
- **Resource Usage**: High (requires database-management)

#### `elk` (Elasticsearch, Logstash, Kibana)
- **Purpose**: Log aggregation and analysis stack
- **Default**: ❌ Disabled
- **Resource Usage**: High

#### `debezium` (Change Data Capture)
- **Purpose**: Stream database changes in real-time
- **Default**: ❌ Disabled
- **Requires**: PostgreSQL (database-management)

#### `golden-image` (Pre-built Docker Layer)
- **Purpose**: Faster Docker builds by caching dependencies
- **Default**: ✅ Enabled
- **Benefit**: Reduces build time from minutes to seconds

### Enable/Disable

```bash
# Edit .tdk/project.json
{
  "optional_infra": {
    "monitoring": true    # Enable
  }
}

# Regenerate
tdk config regenerate
```

## Resource-Level Features

Resource-level features are configured in each `service.json` file via the `features: []` array.

### Frontend Services

Default features for frontend services (appType: "frontend"):

```json
{
  "appName": "my-app",
  "appType": "frontend",
  "features": ["api-client", "env-config", "api-index"]
}
```

#### `api-client`
- **Generates**: `.autogenerated/api-client.ts`
- **Purpose**: Pre-configured API client wrapper for backend communication
- **Imports**: `import { apiClient } from './.autogenerated/api-client'`
- **Customize**: Edit `service.json` → `apiClient` config section

#### `env-config`
- **Generates**: `.autogenerated/env.ts`
- **Purpose**: Environment constants and configuration
- **Imports**: `import { API_URL } from './.autogenerated/env'`
- **Default**: Uses `VITE_API_URL` env var with fallback to local dev URL

#### `api-index`
- **Generates**: `.autogenerated/api-index.ts`
- **Purpose**: Barrel export for cleaner imports
- **Imports**: `import { apiClient, API_URL } from './.autogenerated'`

### Backend Services

Default features for backend services (appType: "backend", "worker", "migrator"):

```json
{
  "appName": "my-api",
  "appType": "backend",
  "features": ["prisma"]
}
```

#### `prisma`
- **Generates**: `.autogenerated/prisma.config.autogenerated.ts`
- **Purpose**: Prisma CLI configuration for database access
- **Usage**: `npx prisma generate`, `npx prisma migrate`, `npx prisma db push`
- **Database**: Uses `DATABASE_URL` env var from project-level database

### Enable/Disable Features

**To enable a feature**, add it to `features: []`:

```json
{
  "features": ["api-client", "env-config", "api-index", "prisma"]
}
```

**To disable a feature**, remove it from `features: []`:

```json
{
  "features": ["api-client"]  // Only api-client runs
}
```

After editing `service.json`, regenerate:

```bash
tdk config regenerate
```

## Always-Enabled Generators

These generators always run and don't have a feature flag:

- **vite** - Frontend/backend build configuration
- **tsconfig** - TypeScript configuration (local and Docker)
- **dockerfile** - Container configuration
- **npmrc/bunfig** - Package manager configuration
- **nginx** - Static file serving (frontend)
- **env** - Backend environment setup
- **agents-md** - AI safety guard rail

## Examples

### Disable API Client Generation

```json
{
  "appName": "dashboard-app",
  "appType": "frontend",
  "features": ["env-config", "api-index"]  // Remove api-client
}
```

### Backend Without Prisma

```json
{
  "appName": "worker",
  "appType": "backend",
  "features": []  // No prisma
}
```

### Enable Monitoring

```json
{
  "optional_infra": {
    "monitoring": true
  }
}
```

Then run `tdk config regenerate && tdk up`.
